## Rationale & Testing Notes

### Landing Page Testing Priority
1. **Variant A (Outcome-Focused)** — Clear benefit, time-bound promise
2. **Variant B (Pain-Point)** — Addresses hesitation directly
3. **Variant D (Speed/Experimentation)** — Appeals to tester mindset
4. **Variant F (System/Process)** — Appeals to operators who want cadence

### Product Page Testing Priority
1. **Variant A (Value-First)** — Standard high-converting structure
2. **Variant B (Risk-Reversal)** — Reduces purchase anxiety
3. **Variant H (Time-Saver)** — Quantifies value clearly
4. **Variant G (Specificity)** — Reduces ambiguity about deliverables

### Lead Magnet Testing Priority
1. **Variant A (Outcome-Focused)** — Clear what they get
2. **Variant B (Specificity)** — 7-day plan is concrete
3. **Variant E (Low-Commitment)** — Reduces signup friction
4. **Variant G (Quick Win)** — Weekend timeline is actionable

### Implementation Notes
- Each variant should be A/B tested with clear success metrics (CTR, conversion rate, email signup rate)
- Use UTM parameters or session storage to track which variant a user saw
- For product pages, consider dynamic variant selection based on traffic source
- Lead magnet variants should be tested against signup rate and downstream email engagement

### Next Steps
1. Implement variant rotation system in `main.ts`
2. Add analytics tracking for variant exposure and conversion
3. Set up A/B test dashboard in Paperclip
4. Document winning variants and promote to default copy
